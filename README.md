# Контроль кассовой дисциплины

FastAPI + Postgres и интерфейс React в стиле Форте Банка. Видео анализируется локально на CPU.
Модель подключена (`model_service.py` + пакет `ml/`): детектор RT-DETRv2 (ONNX), трекинг
ByteTrack, признаки DINOv2-small, таймлайн сцены и правила с цитатами только из
`rules/rules_db.json`. **Веса не хранятся в Git** (обучены на данных хакатона): распакуйте
переданный архив в `models/` (см. раздел «Модель и локальные правила»).

## Запуск в Windows PowerShell

Существующий `.env` уже содержит рабочий секрет. **Не копируйте поверх него шаблон, не
генерируйте новый ключ и не публикуйте файл.** Скрипты запуска не открывают `.env`: его читает
Docker Compose. Нужны Docker Desktop с Linux engine и ранее настроенный ngrok 3.20+.

```powershell
cd C:\dataprompt
# Сначала запустите Docker Desktop и дождитесь готовности Linux engine.
.\scripts\start-public.ps1
```

Скрипт собирает/запускает контейнеры, ждёт `/health`, затем запускает ngrok. Оставьте его окно
PowerShell открытым. Параметры:

```powershell
.\scripts\start-public.ps1 -Domain reverence-culpable-cupping.ngrok-free.dev
.\scripts\start-public.ps1 -NgrokPath 'C:\path\to\ngrok.exe'
```

Публичный интерфейс: https://reverence-culpable-cupping.ngrok-free.dev/ .
Локальный интерфейс: http://localhost:8000/ . Авторизация жюри — заголовок `X-API-Key`;
ключ передаётся отдельно и никогда не встраивается в браузер.

Проверка и остановка из другого PowerShell:

```powershell
.\scripts\check-public.ps1
.\scripts\check-public.ps1 -Video 'C:\data\video.mov'
.\scripts\stop-public.ps1
```

Проверка без видео не читает ключ. Проверка с видео читает только `API_KEY` из `.env` внутри
Python и вызывает `tools/test_client.py` в том же процессе: ключ не попадает в аргументы
дочернего процесса и не выводится. Кадры проверки сохраняются в `.test-artifacts/evidence/`.
Скрипт остановки завершает только ngrok, запущенный нашим скриптом и записанный в локальном
файле состояния с PID/временем старта; чужие процессы не затрагиваются. Если ngrok запущен
вручную, остановите его в исходном окне через Ctrl+C. Compose `down` сохраняет Postgres.

После выключения ноутбука: подключите питание/сеть, запустите Docker Desktop, затем снова
`start-public.ps1` и `check-public.ps1`. Статический домен остаётся тем же; соединение активно,
пока работает туннель. Скрипты не настраивают и не хранят токен ngrok. При ошибке авторизации
настройте ngrok отдельно и повторите запуск. `start-public.ps1` работает в переднем плане,
подавляет сырые сообщения ngrok и при завершении останавливает свой туннель; Docker остаётся
запущенным до `stop-public.ps1`.

Если туннель уже запущен пользователем, достаточно обновить локальный сервис:

```powershell
docker compose config --quiet
docker compose up -d --build --force-recreate
curl.exe http://localhost:8000/health
```

Не запускайте второй ngrok поверх действующего туннеля. Развёрнутый образ не требует Node.js
или подключения к интернету для работы. Для запуска уже собранных/загруженных образов офлайн:
`docker compose up -d --no-build --pull never`. Первая сборка требует образов и Python-пакетов.

## Фронтенд и повторяемая сборка

Исходники: `frontend/forte-cashier-guard-main/` — React 18, TypeScript, Vite, CSS. Дизайн Айдына,
локальные логотипы, шрифты, плеер, drag-and-drop, прогресс, таймлайн и увеличение кадров сохранены.
Сценарии browser mock и выбор источника сохранены в `archive/`, исключены из компиляции и UI.
Логина, истории, экспорта и пакетной загрузки нет; соответствующие серверные функции не добавлялись.

```powershell
.\scripts\build-frontend.ps1
```

Нужен локальный Node.js с npm (проверены Node 24.16.0, npm 11.13.0). Скрипт выполняет `npm ci`
по lockfile, `npm run build`, сохраняет прежнюю страницу как `static/index.legacy.html` и
копирует результат в `static/`. Результат сборки коммитится; исходники, node_modules и кеши
в Docker-образ не включаются. После сборки пересоберите API-контейнер.

Для разработки: `cd frontend/forte-cashier-guard-main`, `npm ci`, `npm run dev`.
Dev-прокси обслуживает `/ui/api` и `/health`. Браузер использует только относительные URL,
никаких `VITE_API_KEY` / `VITE_API_BASE` и внешних CDN. Все шрифты/изображения локальные.
Неизвестный GET-путь интерфейса возвращает SPA, но API, health и отсутствующие ресурсы — 404.

## Настройки

Compose читает существующий `.env` и переменные окружения процесса. Прямой `uvicorn main:app`
не загружает `.env` автоматически. После смены окружения пересоздайте API-контейнер.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_KEY` | Обязательна в Compose | Существующий секрет жюри, не менять и не публиковать |
| `WORKERS` | `1` | Потоки модели внутри одного процесса API |
| `INCLUDE_RULE` | `true` | `false` убирает дополнительное поле `rule` из ответа жюри |
| `RULE_IN_DESCRIPTION` | `true` | При `INCLUDE_RULE=false` добавляет ` Правило: <rule>` к описанию |
| `JOB_TIMEOUT_SEC` | `270` | Секунды с создания задачи, включая очередь |
| `EVIDENCE_FRAMES` | `3` | От 1 до 3 кадров: до, в момент и после события; дубликаты у границ удаляются |
| `UPLOAD_DIR` | `/data/uploads` в Compose | Временные видео; каталог принадлежит только сервису |
| `DATABASE_URL` | `postgresql://app:app@db:5432/app` | Локальный Postgres в Compose |
| `MODEL_DIR` | `/app/models` | Локальные веса, read-only bind mount `./models` |
| `DEMO_MODE` | `false` | Только для теста UI без настоящей модели; не включать для жюри |

Для точной официальной схемы нужен `INCLUDE_RULE=false` (в существующем `.env` пользователь
уже настроил нужные значения). UI всегда получает `description` и строку `rule` раздельно.
Новые настройки имеют безопасные значения по умолчанию; изменять секретный файл для них не нужно.

`models/` и `data/` могут быть пустыми. Локальные нормативные данные монтируются read-only
как `./data:/app/data`. Работайте с **одним процессом uvicorn и одним API-контейнером** для
этой базы и каталога загрузок. При `WORKERS>1` модель и lookup должны быть потокобезопасны.

Postgres хранит задачи и JPEG-доказательства в `pgdata`. Видео удаляются при завершении
обработки/ошибке, отмене задачи в очереди или следующем старте после сбоя. Завершённые задачи
сохраняются после `restart api` и `down`/`up`; не используйте `down -v`, если нужны данные.

## API

Подробная инструкция для жюри: [docs/JURY_INSTRUCTIONS.md](docs/JURY_INSTRUCTIONS.md).

- `POST /api/v1/analyze`: `X-API-Key`, multipart `file`, ответ `{"job_id":"..."}`.
- `GET /api/v1/jobs/{job_id}`: `processing`, `done` или `failed`.
- `POST /ui/api/analyze` и `GET /ui/api/jobs/{job_id}`: тот же процесс без ключа для UI.
- `/health`: `status`, `model_loaded`, `workers`, `demo_mode`.

Ошибки: 401 без/с неверным ключом, 400 пустой файл, 413 свыше 200 МиБ (209715200 байт),
422 без multipart-поля `file`, 404 неизвестная задача. Нечитаемый ролик принимается как задача,
затем получает `failed` с понятной технической ошибкой. UI показывает её мелким текстом под
дружелюбным сообщением. Внешний текст React экранирует; HTML из API не вставляется.

Формат результата не менялся: `verdict=violation|no_violation`, `violations[]` с типом, временем,
описанием и 1–3 JPEG-кадрами в base64 без префикса `data:`. По умолчанию запрашиваются кадры за секунду до события, в момент события и через секунду после. На краях/коротких видео их может быть меньше; кадр события сохраняется всегда.
При неудачном seek выбирается ближайший читаемый кадр; его время может отличаться от события.
У времени кадра без FPS-метаданных приблизительная шкала 30 кадров/с.

## Модель и локальные правила

См. контракт: [docs/MODEL_INTEGRATION.md](docs/MODEL_INTEGRATION.md), описание модели,
метрики и лицензии: [docs/MODEL.md](docs/MODEL.md).

- `model_service.py` загружает модель один раз при старте и отдаёт `type`, `timecode_sec`,
  `description` (что видно + оценка модели 0–1 + «требуется проверка») и `rule`
  (документ, пункт и дословная цитата из `rules/rules_db.json`; модель цитаты не генерирует).
- Веса (≈160 МБ, в Git не входят) кладутся так:
  ```
  models/detector/detector.onnx, config.json, preprocessor_config.json
  models/encoder/dinov2-small/   (config.json, model.safetensors, preprocessor_config.json)
  models/heads.joblib
  models/rule_params.json
  ```
  `./models` монтируется read-only в `/app/models`. Проверка: `/health` → `model_loaded: true`.
- Число потоков CPU: `FORTE_THREADS` (по умолчанию 6 в compose). `WORKERS=1`.

Демонстрационный режим допускается только явно через переменную процесса `DEMO_MODE=true`
при отсутствии `model_service.py`. Он возвращает одно событие «ДЕМО» с явной пометкой,
предупреждает при старте и показывает `demo_mode=true`. Для жюри он должен быть выключен.

## Тесты и измерения

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
```

Проверяются API-контракт (сохранённый snapshot не менялся), auth, обе группы маршрутов,
состояния задач, JPEG-декодирование, правила, deadline, demo-защита, тайм-аут очереди, очистка,
SPA, отсутствие внешних ресурсов в собранном HTML/JS/CSS и ошибки CLI. Синтетические ролики
генерируются OpenCV; датасет не нужен. Live integration без `BASE_URL` и `API_KEY` пропускается.
`tools/verify_stack.py --restart` проверяет текущий локальный стек и сохранность задачи после
рестарта, читая ключ внутри процесса и не выводя его.

```powershell
.venv\Scripts\python tools/verify_stack.py --restart
.\scripts\check-public.ps1 -Video 'C:\data\video.mov'
```

`tools/test_client.py`, `load_test.py`, `eval_labels.py` сохраняют прежний формат вызова
`BASE_URL API_KEY VIDEO...`; ключ приватный, не вставляйте его в документы/снимки экрана.
Есть `--help`, лимиты HTTP-запросов, общий дедлайн и ненулевой код при ошибке. Для повседневной
проверки используйте скрипт, чтобы ключ не передавался в аргументах процесса.
Оценка меток сообщает точность вердикта и попадания таймкода среди верно предсказанных положительных
роликов; пропущенные видео дают ошибку. Пустая база правил и заглушка не дают оценки качества.

Пять видео, один worker и 270 секунд общего бюджета требуют примерно **<54 секунд на видео**,
плюс запас на передачу/опрос до лимита жюри 300 секунд. Дополнительные workers могут ухудшить
скорость из-за конкуренции за CPU. Очередь пока не ограничена; публичные UI-маршруты тоже
потребляют ресурсы. Python не может убить поток: watchdog выставляет `failed`, но зависшая
модель держит worker/файл до возврата. Перезапуск контейнера прекращает её и очищает остатки
при старте. Модель должна сама проверять monotonic deadline и возвращать частичный результат.

## Питание ноутбука перед показом

В PowerShell от администратора, **только для работы от сети (AC)**:

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 0
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
```

Эти команды отключают сон, гибернацию, выключение экрана и действие закрытия крышки от сети.

электропитания. Команды здесь только документированы, автоматически не выполняются.

## Перед передачей жюри

1. Подключить настоящую модель/правила; `/health`: `model_loaded=true`, `demo_mode=false`.
2. Проверить `.mov` до ~29 МБ через публичный URL, обе авторизационные ошибки и точную схему.
3. Измерить длинный ролик и пять одновременных загрузок на этом Intel CPU.
4. Проверить страницу с другой сети, кадры/таймкоды/правила и стабильность после рестарта API.
5. Передать публичный UI/API адрес, ключ отдельно и `docs/JURY_INSTRUCTIONS.md`; приложить
   документы команды о моделях, источниках норм, типах нарушений и ограничениях.
6. Оставить ноутбук на питании, Docker и один ngrok запущенными; не менять адрес/секрет во время проверки.

Проверенные действия и оставшиеся ограничения: [docs/FRONTEND_INTEGRATION.md](docs/FRONTEND_INTEGRATION.md).
`docs/HANDOFF.md` и `docs/VERIFICATION.md` сохраняют историю первого этапа (старый Mode B).

## Диагностика

| Симптом | Что проверить |
|---|---|
| Docker pipe недоступен | Docker Desktop / Linux engine и права на Docker API |
| Сервис не готов | `docker compose ps`, `docker compose logs api db` локально, без публикации секретов |
| ngrok не найден / старый | Путь `-NgrokPath`, версия 3.20+, установленный ngrok |
| Ошибка авторизации ngrok | Отдельная настройка существующего аккаунта, не передавать токен скрипту |
| Предупреждение браузера ngrok | Открыть сайт и подтвердить; API-клиент может передать `ngrok-skip-browser-warning: 1` |
| Модель не загружается | Нет весов в `models/` (см. «Модель и локальные правила»); смотреть `docker compose logs api` |
| Видео не проигрывается в браузере | Неподдерживаемый кодек предпросмотра; сервер всё равно получает оригинальный файл |
| Тайм-аут | Очередь/CPU/зависшая модель/медленная загрузка; измерить, сократить модель, соблюдать deadline |
| Интерфейс старый | Пересобрать frontend, затем пересоздать API-контейнер; обновить страницу |


## День проверки жюри: рабочий порядок

До начала проверки запустите Docker Desktop, подключите питание и сеть. Существующий
ngrok не перезапускайте. После выключения питания, когда туннель действительно остановлен,
запустите `scripts/start-public.ps1 -NoBuild` для уже собранных образов. Если код менялся,
выполните сборку заранее, не во время автоматической проверки.

```powershell
.\scripts\status.ps1
.\scripts\prepare-handover.ps1 -AllowStub
.venv\Scripts\python -X utf8 tools/check_model.py --video 'C:\data\video.mov'
.venv\Scripts\python -X utf8 tools/bench_model.py --videos 'C:\data\videos' --count 5 --workers 1 --sweep
```

Без модели первые проверки отмечают WARN/FAIL, а модельные инструменты завершаются понятным
сообщением: это ожидается. `-AllowStub` не маскирует грязный Git, проблемы публичного URL и
неудалённую заметку о модели в инструкции жюри. Текущая `.vscode/` — пользовательские
некоммиченные файлы; решите их судьбу самостоятельно перед финальной передачей.

После подключения настоящей модели проверьте качество/скорость и выполните:

```powershell
.\scripts\prepare-handover.ps1 -Finalize
# Удаление предварительной заметки меняет документ: просмотрите и закоммитьте изменение.
git add docs/JURY_INSTRUCTIONS.md
git commit -m "docs: finalize jury instructions after model verification"
.\scripts\prepare-handover.ps1
.\scripts\make-clean-zip.ps1 -Out '.\.test-artifacts\dataprompt-clean.zip'
```

`-Finalize` вызывает отдельный `finalize-jury-doc.ps1` только по явному флагу. Он откажется
удалять блок, пока `/health` не покажет `model_loaded=true`, `demo_mode=false`. Если документ
изменён, pre-flight остаётся FAIL до коммита. Сам скрипт не делает коммит автоматически.
Архив содержит только `git archive HEAD`, не рабочие изменения. По умолчанию архив создаётся
на рабочем столе как `dataprompt-clean.zip`; `-Out` задаёт другое место. Перед записью в памяти
проверяются запрещённые файлы и отсутствие реального ключа; выводятся только счётчики.

`status.ps1` показывает контейнеры, local/public health, состояние записанного процесса ngrok
и безопасные метаданные из последних 20 строк API-журнала. Необработанные строки с payload
не выводятся. В штатной проверке следите за health, очередью/временем CPU и доступностью URL.
Во время загрузок жюри не перезапускайте контейнеры, туннель, ноутбук и не меняйте ключ.

Инспектор ngrok: http://127.0.0.1:4040 — локальный список запросов, их HTTP-статусы и время.
Он может показывать реальные заголовки/содержимое: не публикуйте его скриншоты, логи и не
копируйте ключ из запросов. Проверяйте 200 для upload/poll и отсутствие 5xx/обрывов. Данные
инспектора не являются измерением длительности модели; используйте benchmark и логи задач.

При отказе после отключения питания: дождитесь готовности Docker, `start-public.ps1 -NoBuild`,
затем `status.ps1` и `check-public.ps1`. Если локальный API здоров, а public нет — проверьте
сеть/существующий туннель в инспекторе; не запускайте второй ngrok. Перезапуск допускается
только до/после проверки и после выяснения причины. Настройки бодрствования от сети приведены выше.

Все `scripts/*.ps1` сохранены как UTF-8 с BOM; Git использует CRLF при checkout. BOM нужен
Windows PowerShell 5.1 для русского текста. Регрессионный тест проверяет BOM и реальный
парсер PowerShell 5.1. Не пересохраняйте скрипты как UTF-8 без BOM.
