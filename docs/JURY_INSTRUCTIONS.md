# Инструкция для жюри: контроль кассовой дисциплины

## Адреса и назначение

Интерфейс: https://reverence-culpable-cupping.ngrok-free.dev/

API: https://reverence-culpable-cupping.ngrok-free.dev/api/v1

Заголовок авторизации: `X-API-Key: <КЛЮЧ ПЕРЕДАЁТСЯ ОТДЕЛЬНО>`.

Сервис предназначен для выявления видимых признаков возможных нарушений кассовой дисциплины
на видеозаписи. Он показывает тип события, таймкод, описание, нормативное правило и JPEG-кадры.
Результат — подсказка для проверки человеком, а не окончательное юридическое заключение.
Модели выполняются локально на CPU компьютера сервиса, без облачных сервисов искусственного
интеллекта; звук не анализируется и лица не идентифицируются.

## Через браузер

Откройте интерфейс, выберите или перетащите один файл `.mov`, дождитесь загрузки и анализа.
Результат: «Нарушение не обнаружено» либо «Обнаружены признаки возможных нарушений».
События содержат время в формате мм:сс, описание, правило/источник и кадры. Нажмите на кадр
для увеличения; на таймкод — для перехода к моменту в локальном видеоплеере.
Неподдерживаемый браузером кодек может отключить предпросмотр, но не отправку файла на сервер.

На бесплатном ngrok в браузере может появиться предупреждение `ERR_NGROK_6024`.
Подтвердите переход на сайт. Программный клиент может обойти браузерное предупреждение
заголовком `ngrok-skip-browser-warning: 1` (добавлен в примеры ниже).

## Через API (Windows PowerShell, curl.exe)

Ключ выдаётся отдельно. В примерах замените плейсхолдер локально; не публикуйте получившуюся
команду с ключом. Multipart-поле называется строго `file`.

```powershell
curl.exe -X POST https://reverence-culpable-cupping.ngrok-free.dev/api/v1/analyze -H "X-API-Key: <КЛЮЧ ПЕРЕДАЁТСЯ ОТДЕЛЬНО>" -H "ngrok-skip-browser-warning: 1" -F "file=@video.mov"
curl.exe https://reverence-culpable-cupping.ngrok-free.dev/api/v1/jobs/ЗАМЕНИТЕ_НА_JOB_ID -H "X-API-Key: <КЛЮЧ ПЕРЕДАЁТСЯ ОТДЕЛЬНО>" -H "ngrok-skip-browser-warning: 1"
```

POST возвращает HTTP 200:

```json
{"job_id":"..."}
```

Опрашивайте GET примерно каждые две секунды. Ответ содержит один из трёх статусов:

```json
{"job_id":"...","status":"processing"}
```

```json
{"job_id":"...","status":"failed","error":"техническое описание ошибки"}
```

```json
{"job_id":"...","status":"done","verdict":"no_violation","violations":[]}
```

Точная схема положительного результата (при `INCLUDE_RULE=false`, дополнительного поля `rule` нет):

```json
{
  "job_id":"...",
  "status":"done",
  "verdict":"violation",
  "violations":[
    {
      "type":"Тип события от модели",
      "timecode_sec":44.2,
      "description":"Видимые признаки и объяснение. Правило: документ и пункт от локального источника",
      "evidence_frames":[
        {"timestamp_sec":44.2,"image_base64":"BASE64_БАЙТОВ_JPEG"}
      ]
    }
  ]
}
```

`verdict` — строго `violation` или `no_violation`. Время — неотрицательные секунды; 1–3 JPEG-кадра
на событие, base64 без префикса `data:`. При неудачном поиске кадра его время может отличаться
от таймкода события. Если нормативное правило доступно, оно включается в `description` при
`RULE_IN_DESCRIPTION=true`; в браузерном UI оно отображается отдельным блоком.

Без ключа или с неверным ключом — HTTP 401. Нет `file` — 422; пустой файл — 400;
превышение лимита — 413; неизвестный `job_id` — 404. Нечитаемый ролик даёт задачу `failed`.

## Ограничения и данные

Формат подачи — `.mov`, типичный объём тестовых видео до ~29 МБ; технический предел файла
200 МиБ (209715200 байт). Лимит ожидания результата — 5 минут на видео. Тайм-аут сервиса
по умолчанию 270 секунд, включая очередь; время передачи дополнительно. Несколько
одновременных роликов делят CPU, поэтому фактическую скорость необходимо измерять.

Загруженные видео удаляются после обработки; задачи и JPEG-доказательства сохраняются в
Postgres. При зависшем Python-потоке видео удаляется после возврата потока либо на следующем
старте контейнера. Watchdog отмечает такую задачу как `failed`; поток не может быть убит отдельно.

## Локальный запуск

1. Запустите Docker Desktop с Linux engine на Windows / Intel CPU.
2. Используйте существующий `.env` с отдельно предоставленным ключом; не публикуйте его.
3. Из каталога проекта выполните:

```powershell
docker compose up -d --build
curl.exe http://localhost:8000/health
```

Откройте http://localhost:8000/ . Веса модели находятся в `models/`, локальные правила — в
`data/` либо локальном Postgres. После предварительной сборки и наличия весов обработка
не требует интернета: `docker compose up -d --no-build --pull never`.
Для публичного доступа команда запускает `scripts/start-public.ps1`; туннель требует сети,
но никакое облачное AI API в обработке не участвует.
Остановка: `scripts/stop-public.ps1` (данные Postgres сохраняются).
