# Эксплуатация сервиса

Руководство для компьютера, на котором работает итоговый сервис. Сценарий проверки
жюри — в [JURY_INSTRUCTIONS.md](JURY_INSTRUCTIONS.md), архитектура и результаты —
в [README](../README.md) и [MODEL.md](MODEL.md).

## Первый запуск

Нужны Docker с Compose, полный комплект весов и приватный `.env`.
На Windows используйте Docker Desktop с Linux engine. Исходники клонируются из GitHub;
веса (~160 МБ) передаются отдельно в `models/`. Точный состав — в
[MODEL_INTEGRATION.md](MODEL_INTEGRATION.md). Пустой каталог моделей не подходит.
База норм уже включена в `rules/rules_db.json`.

Для нового клона скопируйте `.env.example`, только если `.env` отсутствует, и настройте
длинный случайный `API_KEY`, `INCLUDE_RULE=false`. Не заменяйте существующую рабочую
конфигурацию. Затем из корня проекта:

```powershell
docker compose up -d --build
curl.exe http://localhost:8000/health
```

Ожидаются `status=ok`, `model_loaded=true`, `demo_mode=false`.
Локальный интерфейс: <http://localhost:8000/>. Первая сборка требует сети для образов,
системных библиотек и Python-пакетов. Уже собранный стек с весами запускается без
загрузок: `docker compose up -d --no-build --pull never`.

## Публичный доступ

ngrok должен быть установлен и заранее авторизован на компьютере хоста.
Токен ngrok и ключ приложения — разные секреты: жюри получает только `API_KEY`.
Скрипт ищет `ngrok` в PATH, затем использует запасной путь Windows; доступен `-NgrokPath`.

Если туннель ещё не работает:

```powershell
.\scripts\start-public.ps1 -NoBuild
```

Скрипт запускает Compose и один туннель, записывает идентификатор своего процесса
в игнорируемый файл `.public-session.json`. Оставьте это окно PowerShell открытым.
При изменении исходников предварительно соберите образ либо запускайте без `-NoBuild`.
Не запускайте второй туннель поверх действующего.

Для другого домена/расположения ngrok:

```powershell
.\scripts\start-public.ps1 -NoBuild -Domain your-domain.ngrok-free.app -NgrokPath 'C:\tools\ngrok.exe'
```

Командный адрес: <https://reverence-culpable-cupping.ngrok-free.dev/>.
При переносе хоста тот же адрес доступен через авторизованный агент того же ngrok-аккаунта;
старый туннель должен быть остановлен. На новом хосте установите значение `API_KEY`,
совпадающее с формой сдачи, либо исправьте ключ в форме. Работа браузерного UI сама по себе
не подтверждает правильность ключа: UI использует отдельные маршруты без jury-ключа.

## Диагностика

```powershell
.\scripts\status.ps1
.\scripts\check-public.ps1
.\scripts\check-public.ps1 -Video 'C:\data\video.mov'
```

Проверка с видео выполняет настоящий upload и сохраняет кадры в `.test-artifacts/evidence/`.
Без видео проверяются доступность и отказ без ключа. Ключ читается внутри процесса,
не выводится и не передаётся аргументом дочерней программы.
`status.ps1` показывает health и безопасные метаданные журнала.

Инспектор ngrok: <http://127.0.0.1:4040>. Он может содержать заголовки и данные запросов:
не публикуйте его скриншоты и сырые логи. Предупреждение ngrok в браузере можно подтвердить;
программный клиент передаёт `ngrok-skip-browser-warning: 1`.

| Симптом | Причина или действие |
| --- | --- |
| `NO_SUCHFILE ... detector.onnx` | Неполный `models/` или неправильный bind mount; получить полный обученный комплект |
| Ошибка загрузки энкодера/классификатора | Проверить `encoder/dinov2-small/`, `heads.joblib`, версии пакетов и соответствие `ml/` весам |
| Docker pipe недоступен | Дождаться готовности Docker Desktop / Linux engine |
| Public недоступен, local работает | Проверить сеть, ngrok-аккаунт, домен и существующий туннель |
| UI работает, jury API даёт 401 | Сверить ключ формы с `API_KEY` на фактическом хосте |
| Предпросмотр видео не работает | Браузер может не поддерживать кодек; оригинал всё равно отправляется на сервер |
| Задание получает `failed` по времени | Очередь, скорость CPU, передача файла или длительный инференс; смотреть измерения и состояние хоста |
| Интерфейс не обновился | Пересобрать фронтенд, затем API-образ вне времени проверки |

## Конфигурация

Compose читает `.env`; прямой `uvicorn main:app` не загружает его автоматически.
После изменения окружения API-контейнер пересоздаётся вне времени проверки.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `API_KEY` | Обязательна | Ключ jury API на этом хосте |
| `WORKERS` | `1` | Один обработчик для общего Analyzer |
| `FORTE_THREADS` | `6` в Compose | Потоки CPU-инференса |
| `INCLUDE_RULE` | `true` | Для jury-схемы установить `false` |
| `RULE_IN_DESCRIPTION` | `true` | Добавлять норму в описание при `INCLUDE_RULE=false` |
| `JOB_TIMEOUT_SEC` | `270` | Бюджет задания вместе с очередью |
| `EVIDENCE_FRAMES` | `3` | Допустимо 1–3 JPEG на событие |
| `MODEL_DIR` | `/app/models` | Стандартный read-only mount весов |
| `UPLOAD_DIR` | `/data/uploads` | Временные видео |
| `DATABASE_URL` | Локальный PostgreSQL в Compose | Хранилище результатов |
| `DEMO_MODE` | `false` | В итоговом сервисе выключен |
| `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` | `1` в Compose | Использовать локальные модельные файлы |

Модуль модели меняет параметры общего Analyzer между запросами; сохраняйте `WORKERS=1`.
Watchdog отмечает просроченное задание как `failed`, но не может убить Python-поток.
Текущий адаптер при малом остатке бюджета увеличивает шаг детекции; частичный ответ
по дедлайну он не возвращает. Подробности — в контракте интеграции.

## Данные и остановка

PostgreSQL хранит задания и кадры в volume `pgdata`. Видео удаляются после обработки;
при зависшем потоке файл остаётся до возврата потока или очистки на следующем старте.
`restart api` и обычный `down` сохраняют результаты; `down -v` удаляет volumes.

Остановка вне проверки:

```powershell
.\scripts\stop-public.ps1
```

Скрипт завершает только записанный им процесс ngrok и останавливает Compose.
Вручную запущенный ngrok останавливается в исходном окне.
Не останавливайте стек и туннель во время запросов жюри.

## Перезапуск после выключения

Подключите питание и сеть, запустите Docker Desktop, дождитесь Linux engine.
Если туннель действительно остановлен:

```powershell
.\scripts\start-public.ps1 -NoBuild
```

Из второго окна выполните `status.ps1` и `check-public.ps1`.
Для проверки жюри хост остаётся включённым, подключённым к питанию и сети, без сна.
При необходимости отключите сон от сети в настройках Windows. Администратор может
применить следующие настройки AC, вернув обычные значения после мероприятия:

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
powercfg /setactive SCHEME_CURRENT
```

## Разработка и проверка конфигурации

```powershell
.\scripts\build-frontend.ps1
.venv\Scripts\python -m pytest -q
.\scripts\prepare-handover.ps1
```

Фронтенд собирается локальным Node/npm; готовый результат коммитится в `static/`.
Все `.ps1` используют UTF-8 с BOM и CRLF для Windows PowerShell 5.1.
Тесты приложения используют модельные заглушки. Legacy live-stack test и
`tools/verify_stack.py --restart` предназначены для тестового стека с заглушкой;
не используйте их для перезапуска итогового хоста.

Preflight проверяет модель, конфигурацию, публичный доступ без ключа, приватность,
локальные ресурсы, чистоту Git и финальную инструкцию. Он запускается на хосте:
проверка чистого Git не включает личные файлы в коммит автоматически.
Финальная инструкция уже оформлена; `-Finalize` для неё не нужен.

## Чистый архив исходников

```powershell
.\scripts\make-clean-zip.ps1 -Out '.\.test-artifacts\dataprompt-clean.zip'
```

Архив содержит только закоммиченный HEAD. Он исключает `.env`, исходные видео,
кеши и модельные веса; секрет проверяется перед сохранением без вывода значения.
Для переноса полного сервиса отдельно нужны доверенный архив `models/`, приватная
конфигурация и при необходимости резервная копия PostgreSQL. ZIP исходников не является
резервной копией модели или базы данных.
